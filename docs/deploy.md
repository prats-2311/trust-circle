# Deploying Trust Circle (free tier)

Render hosts the web service, Neon hosts Postgres, and GitHub Actions runs the schedules. Everything here is sandbox only. Never paste a secret into a chat or an issue: copy it straight from one dashboard into another.

You need a Render account, a Neon account and a GitHub account. Work through the steps in order.

## 1. GitHub repo

1. Create an empty **public** repository on GitHub (no README or licence; the repo already has an MIT licence). It must be public: the `keep warm` (every 5 minutes) and `expire holds` (every 15 minutes) workflows are about 11,500 runs a month, and public repos get unlimited Actions minutes. A private free repo would run out in about a week and silently stop hold expiry.
2. Push this project to it. Render and the workflows both read from this repo.

## 2. Neon project

1. In Neon, create a project. Pick region **AWS US West 2 (Oregon)**, `aws-us-west-2`, which is close to Render Oregon.
2. Open **Connect** and turn **Connection pooling off**. Copy the **direct** (non-pooled) connection string. It looks like `postgresql://USER:PASSWORD@ep-xxxx.us-west-2.aws.neon.tech/neondb?sslmode=require`. Keep `sslmode=require` (and `channel_binding=require` if Neon adds it). Click **Show password** before copying: Neon masks the password otherwise, and a string without it fails on the first migration query.
3. Keep this string for steps 3 and 4. It goes in your terminal and in Render only.

## 3. Migrate and seed the database (`deploy:seed`)

Run this once, from your machine, in the project folder:

```bash
read -rs DATABASE_URL && export DATABASE_URL && npm run deploy:seed
```

Paste the Neon direct connection string at the silent prompt and press Enter. The password is not echoed and does not land in your shell history. Run `unset DATABASE_URL` afterwards.

- The value must come from the shell environment. The command ignores `.env.local` on purpose, and refuses a localhost database.
- It prints only the database host and waits. Type that host and press Enter to confirm.
- It then applies every migration, adds the demo people, loads the scam patterns (the first run downloads a 23 MB model) and seeds the demo history.

## 4. Render Blueprint

1. In Render choose **New > Blueprint** and connect the GitHub repo. Render reads `render.yaml` and proposes the `trust-circle` web service on the free plan.
2. Enter every value Render asks for **before the first build**. `NEXT_PUBLIC_*` values are read at build time, so a value added later needs a new build.

| Render variable | Where to copy it from |
|---|---|
| `DATABASE_URL` | Neon direct connection string from step 2 |
| `PAYPAL_CLIENT_ID` | PayPal developer dashboard, Sandbox app |
| `PAYPAL_CLIENT_SECRET` | Same app, Secret key |
| `NEXT_PUBLIC_PAYPAL_CLIENT_ID` | Same value as `PAYPAL_CLIENT_ID` |
| `PAYPAL_WEBHOOK_ID` | Leave a placeholder for now; set it in step 5 |
| `GROQ_API_KEY` | Groq console |
| `GROQ_TEXT_MODEL` | The text model name from your `.env.local` |
| `GROQ_VISION_MODEL` | The vision model name from your `.env.local` |
| `GROQ_AUDIO_MODEL` | Optional. The voice transcription model; defaults to `whisper-large-v3-turbo` |
| `CRON_SECRET` | A random string of at least 24 characters (for example `openssl rand -hex 24`). Keep it: step 7 needs the same value |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Step 10. Leave them empty for now (push stays off) |
| `APP_URL` | The service URL Render gives you, `https://<render-host>` with no trailing slash. Set it after the service is created, then redeploy |

`SESSION_SECRET` is generated by Render, `PAYPAL_ENV` is fixed to `sandbox`, and `DEMO_DAILY_RESET` is `1`.

3. Deploy. The start command applies any new migrations, then starts the server. The first request after a sleep can take about a minute.

## 5. PayPal sandbox webhook

1. In the PayPal developer dashboard, open the Sandbox app, then **Webhooks > Add webhook**.
2. URL: `https://<render-host>/api/paypal/webhook`.
3. Event types:
   - all eight `PAYMENT.PAYOUTS-ITEM.*` events;
   - `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED` and `PAYMENT.CAPTURE.REFUNDED`;
   - `PAYMENT.AUTHORIZATION.VOIDED` and `CUSTOMER.DISPUTE.CREATED`. These are recorded in the audit log only when the event carries a Trust Circle id.
4. Save. Copy the **Webhook ID** into Render as `PAYPAL_WEBHOOK_ID`. Render redeploys.

## 6. Transaction Search (for aftercare)

In the PayPal developer dashboard open the same Sandbox app, then **Features**, and switch on **Transaction Search**. Without it the aftercare review falls back to Trust Circle's own records and says so. Sandbox data can lag by about 3 hours.

## 7. GitHub secret and variable

In the GitHub repo, **Settings > Secrets and variables > Actions**:

- **Secrets** tab: new secret `CRON_SECRET`, with the same value you gave Render.
- **Variables** tab: new variable `APP_URL`, `https://<render-host>` with no trailing slash.

## 8. Run both workflows once by hand

In the repo's **Actions** tab, run `keep warm`, `expire holds` and `demo reset` with **Run workflow**. All three must finish green. A red run with 401 means `CRON_SECRET` differs between GitHub and Render; 404 on `demo reset` means `DEMO_DAILY_RESET` is not `1` in Render. The `keep warm` schedule (every 5 minutes) keeps the web service awake without touching the database. The sweep runs every 15 minutes, so Neon's free compute sleeps between sweeps instead of running all month.

## 9. Smoke test

Run the smoke test (Task 6) against the live site:

```bash
BASE_URL=https://<render-host> npx playwright test e2e/smoke.spec.ts
```

When `BASE_URL` is set, only the `smoke` project runs: the `default` project (the full end-to-end stories, which reset the demo and move sandbox money) matches nothing, so a run against a deployed site can't wipe or change its data.

To smoke-test a production build on your own machine first, run `npm run build`. `npm run start:prod` reads only the process environment, not `.env.local`, so export the variables in a subshell. `set -a; . ./.env.local; set +a` loads them without echoing any value:

Values with spaces or `< >` (such as `ALERT_FROM_EMAIL="Trust Circle <onboarding@resend.dev>"`) must be quoted in `.env.local`, or the shell step above fails to load them.

```bash
# Terminal 1: serve the production build on port 3999
(set -a; . ./.env.local; set +a; PORT=3999 npm run start:prod)
# Terminal 2: run the smoke test against it
BASE_URL=http://localhost:3999 npx playwright test --project smoke
```

## 10. VAPID keys (push alerts)

1. Run `npm run vapid:keys` locally. It prints a public and a private key.
2. In Render set `NEXT_PUBLIC_VAPID_PUBLIC_KEY` (public key), `VAPID_PRIVATE_KEY` (private key) and `VAPID_SUBJECT` (`mailto:` or `https:` address you control).
3. Use Render's **Save, rebuild, and deploy** (or a manual deploy that rebuilds), not a plain restart. `NEXT_PUBLIC_VAPID_PUBLIC_KEY` is set at build time, so a restart will not pick it up.

## Notes

- Schedules from GitHub can run several minutes late, so a hold can expire a few minutes past 72 hours.
- The daily demo reset runs at 09:00 UTC and returns the shared demo to its clean story. Anyone mid-flow at that moment loses their state.
